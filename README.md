# ZipNest

Full-featured archive manager for Windows (x64 + ARM64), built on the
official 7-Zip engine (`7z.dll`, dynamically loaded). Free for everyone —
donations optional, **no feature is ever gated**.

## Status: M1 (engine foundation) — done

The engine layer lives in two crates:

| Crate | Purpose |
| --- | --- |
| `archive-core` | `7z.dll` COM wrapper: open / list / read / extract, passwords, progress, cancellation |
| `archive-security` | Path sanitization (zip-slip, traversal, reserved names) + extraction quota (zip-bomb guard) |

Supported in M1: **ZIP, 7z, RAR, TAR, GZ, BZ2, XZ, ISO** extraction
(RAR decompression only — creating RAR is intentionally unsupported),
plus ZIP/7Z/TAR creation planned for M2+.

## Build & test

```powershell
cargo test --workspace          # 25 tests, must be green
cargo test -- --ignored         # one-off 5000-entry performance probe
```

Fixtures (regenerated by `fixtures/make_fixtures.ps1`, requires 7-Zip):

- `plain.zip` — 4 entries incl. a subdirectory
- `enc.zip` — AES-256 entry-encrypted, password `secret`
- `enc.7z` — **header-encrypted** (`-mhe=on`), password `secret`
- `corrupt.zip` — intentionally broken signatures

## Security model

- **Every** entry path goes through `archive_security::sanitize_entry_path`
  before touching the filesystem — traversal (`..`), absolute/UNC paths and
  Windows device names are rejected, illegal characters are neutralized.
- Extraction writes are bounded by `ExtractQuota`; exceeding it aborts the
  operation with `error.quota_exceeded`.
- Passwords live in memory only: they are never logged and are redacted
  from `Debug` output.
- Progress callbacks return `false` to cancel → `ZipnestError::Cancelled`.

## Error surface

All cross-crate errors are `ZipnestError` with a stable
`error_key() -> "error.*"` constant for the UI/i18n layer; raw engine
HRESULTs are funneled through one choke point (`map_hresult`).
