# ZipNest 文字清晰度改造 — 设计与实测记录

日期：2026-11-14 / 15
范围：`apps/zipnest-native/src/theme.rs` + `apps/zipnest-native/src/main.rs` 的字号、字体栈、配色
目标：让界面文字看起来和 Windows 自己的界面一致——清晰的字体、清晰的粗细、清晰的对比度。

## 一、实测到的现状（不是推测）

截图取的是真实运行中的 `D:\ZipNest\zipnest.exe`（窗口 916×659，DPI 96，缩放 100%）。

| 取样 | 前景最暗像素 | 边缘像素占比（越大越糊） |
|---|---|---|
| Windows 原生标题栏「ZipNest 解压缩」 | 0 | 0.53 |
| ZipNest 空状态大标题（17px） | 80 | 0.60 |
| ZipNest 空状态提示（13px） | 92 | 0.61 |

两件事同时被量出来了：

1. **颜色比 Windows 淡。** 正文用 egui 默认的 `gray(80)`，在 243 的浅灰面板上对比度 7.27:1；提示文字更淡（黑 158/255 alpha → 落到 92），只有 5.99:1。
2. **边缘过渡像素比原生多。** 同一段字，原生 0.53，我们 0.60。

## 二、字体栈

改动前：`segoeui.ttf` + `msyh.ttc`（**索引 0**）+ `consola.ttf`。

改动后：

| 用途 | 文件 | 索引 |
|---|---|---|
| 比例（拉丁） | `C:\Windows\Fonts\segoeui.ttf` | 0 |
| 比例（中文） | `C:\Windows\Fonts\msyh.ttc` | **1 = Microsoft YaHei UI** |
| 粗体（拉丁） | `C:\Windows\Fonts\segoeuib.ttf` | 0 |
| 粗体（中文） | `C:\Windows\Fonts\msyhbd.ttc` | **1 = Microsoft YaHei UI Bold** |
| 等宽 | `CascadiaMono.ttf` → `consola.ttf` | 0 |

**为什么是 YaHei UI（索引 1）。** 这台机器 `HKCU\Control Panel\Desktop\WindowMetrics` 的
`MessageFont`/`CaptionFont`/`IconFont`/`MenuFont`/`StatusFont`/`SmCaptionFont` 六个 LOGFONTW
全部解析成 `lfHeight=-12, lfQuality=5 (ClearType), lfFaceName="Microsoft YaHei UI"`。微软
「Fonts for non-Latin languages」也把 Microsoft YaHei UI 列为简体中文的界面字体，并且本机
`HKLM\...\FontLink\SystemLink` 把 Segoe UI 系列全部链到它。

两个 face 的**字形完全相同**（glyf/loca/hmtx/GSUB/GPOS 逐字节一致），差别只有纵向度量：
face0 hhea 2167/-536（行高 1.3198 em），face1 2080/-521（1.2700 em）。即「UI」版是专为界面
收紧行距的版本。

**为什么拉丁留在 `segoeui.ttf` 而不是 `SegUIVar.ttf`。** 后者是 Win11 shell 实际用的字体，
但只有 2530 个字形（静态版 5395），且数字 `one` 的 advance 是 776 units 对 1104——换过去会
重新排布列表里所有数字，除非强制开 `tnum`，而 epaint 没暴露这个开关。13pt 下两者的字母
度量一致。

## 三、字号

改动前的统计（`git show HEAD`）：12.5×6、11.5×7、12.0×4、13.0×3、18.0×2、11.0/10.5×3、
13.5×2、17.0×1、8.0×1。

改动后全部收敛成 `theme.rs` 里五个常量：

| 常量 | 值 | 用在 |
|---|---|---|
| `TEXT_BADGE` | 8.0 | 列表里文件类型徽标里的三个字母（纸页只有 14pt 宽，刻意低于 TINY） |
| `TEXT_TINY` | 11.0 | 格式标签、`?` 帮助标记 |
| `TEXT_SMALL` | 12.0 | 提示、状态栏、字段下的错误行、搜索命中的目录后缀 |
| `TEXT_BODY` | 13.0 | 正文、表单标题、选项条、列表行名、大小/时间列、搜索结果文件名 |
| `TEXT_SECTION` | 13.0 | 设置页/新建页的分节标题（靠粗体区分） |
| `TEXT_TITLE` | 18.0 | 设置页/新建页/空状态的大标题 |

**一个必须说清的诚实点：整数字号本身并不带来锐度。** 这两款字体（雅黑 UI、Segoe UI）的
`head.flags` 都置了 `FORCE_INTEGER_PPEM`，skrifa 在 hint 前会把 ppem 取整，所以 12.5pt 和
13pt **光栅化结果逐字节相同**，那半个点只影响排版宽度。真正的锐度台阶是字号本身：13px 的
边缘占比 0.60，14px 是 0.556。正文最终留在 13（即 0.60 那一档）——因为 14 会让每一行和
每个控件都长一个点，而更大的收益在别处（见第五节）。

改成整数的实际好处是：刻度落在同一个网格上、新增字号需要显式加常量，而不是随手写一个
`12.5`。

## 四、颜色

| 文字 | 改动前 | 对比度 | 改动后 | 对比度 |
|---|---|---|---|---|
| 正文（浅） | gray(80) | 7.27:1 | `rgb(27,27,27)` | 15.52:1（面板）/ 17.22:1（卡片） |
| 正文（深） | gray(140) | — | `rgb(229,229,229)` | 12.93:1（面板） |
| 次要（浅） | 黑 158α → 92 | 5.99:1 | `rgb(84,84,84)` | 6.82:1（面板）/ 5.86:1（选中底） |
| 次要（深） | 白 196α | — | `rgb(190,190,190)` | 8.77:1（面板）/ 4.57:1（选中底） |
| 输入框占位（浅） | 双重 alpha → 2.96:1 | — | `rgb(112,112,112)` | 4.95:1 |
| 输入框占位（深） | — | 2.64:1 | `rgb(160,160,160)` | 6.66:1 |

次要色是按各自主题里**最难的那个表面**（选中行的底色）选的，因为大小列、时间列会用这个颜色
画在可被选中的行上。

## 五、字体光栅化：真正修掉「糊」的那一个开关

`epaint 0.37` 的 `FontTweak::hinting_target` 里，真正起作用的是
`SmoothHinting::symmetric_rendering`。

开着它（egui 默认，也是之前每个版本的行为）时，带 ClearType 指令的 TrueType 程序（雅黑带
完整的 `fpgm`/`prep`/`cvt `）会按 GETINFO 的「对称平滑」位跑，把横向笔画加宽，让它在**次像素
（RGB 条纹）光栅器**上看着对。epaint 用的是单通道解析式面积光栅器，那些被加宽的笔画没有
次像素可以利用，落成灰边。

**关掉它，在这台机器 13pt 雅黑 UI、`subpixel_binning` 关闭的条件下实测：**

- 完全覆盖（纯实色）像素占墨迹比例：**4.0% → 27.2%**
- 总墨量几乎不变：1005 → 1001
- 真实窗口截图复核（状态栏「3 个项目」）：**27.1% → 48.9%**
- 表头「名称」：**4.5% → 24.4%**

`preserve_linear_metrics` **保持默认**。它在 skrifa 0.44 里只控制
`backward_compatibility` 和 INSTCTRL selector 3；12/13pt 中英两种字面实测位图逐字节相同。
设它是个伪装成修复的空操作。

`subpixel_binning` 关掉。epaint 自己的文档就写着它「让文字看起来更糊」。CJK 汉字本来就被
排除在外，但它对**全角标点**（`，。！？`）照样生效——每个标点会占 4 个图集槽。

**已知范围限制（诚实记录）**：`symmetric_rendering: false` 的收益不是无条件的。实测在
100% 缩放下，18pt 常规字重的拉丁标题墨量反而降约 4%，实心像素占比 13.2% → 12.6%——这是
它唯一反作用的地方。Segoe UI Bold（页面大标题用的）在任何字号下都逐字节相同。125%/150%
缩放下拉丁反而是增墨。

## 六、粗体是真正的粗体

`RichText::strong()` 只改颜色（读 `widgets.active`），不改字重。正文变成近黑之后，这个强调
只剩 1.22:1，等于没了。

所以加载了真正的粗体字面，建了独立字族 `FontFamily::Name("bold")`：

- `segoeuib.ttf`（Segoe UI Bold）+ `msyhbd.ttc` 索引 1（Microsoft YaHei UI Bold）
- 尾部挂常规字面，粗体缺少的字会以常规字重回退，而不是变豆腐块
- 尾部再挂 `Proportional` 的内建尾（`egui-icons`、`Ubuntu-Light`），因为自定义族不会自动
  继承内建字体——否则 `egui::special_emojis` 的私用区码位在粗体族里会是豆腐块
- `msyhbd.ttc` 覆盖本 app 字面量用到的全部 408 个非 ASCII 字符

用法：`theme::emphasis(text)` 而不是 `.strong()`。用在分节标题、页面标题、版本号、反馈邮箱。

工具栏的压缩包名**保持常规字重**：粗体宽约 8%，在 720pt 最小窗口下会把原本放得下的名字
挤成省略号——那是拿功能换装饰。

| 位置 | 问题 | 处理 |
|---|---|---|
| 深色主按钮 | 白字压浅蓝 accent，2.53:1 | `theme::on_accent()` 深色下用 `rgb(20,20,20)`，7.29:1 |
| 无边框按钮悬停 | 正文近黑后，悬停从 27→黑只有 1.22:1 | hovered 文字色改成 accent（5.11:1） |
| 「完成」绿 | 4.28:1，比旁边的次要文字还淡 | `rgb(22,100,42)`，7.27:1 |
| 「有链接没打包」琥珀 | 4.06:1 | `rgb(138,80,2)`，6.50:1 |
| 错误红 | 4.58:1，三个语义色里最淡 | `rgb(160,30,15)`，7.04:1（L\* 34.9，仍是最重的一档） |

| 输入框占位 | 颜色 ×0.6 再乘 0.6 alpha，两次衰减 | `weak_text_color` 固定成不透明值 |

## 八、布局耦合

- `CONTROL_H = 28`：13px 正文 + 上下 padding 正好，未动。它也是字号的**上限**——Segoe UI
  行高 1.330×，超过约 15pt 按钮就会比旁边 28pt 的输入框高。
- `ROW_H = 26`：13px 行高约 17，余量 9pt，未动。
- `TOOLBAR_RIGHT_W = 210`：实测三个按钮合计只占 108–151pt，够用。
- 存档名框：格式标签的宽度先预留出来，名字用剩余宽度，`zip` 不会再画到框外。

## 九、验证与结论

- `cargo test --workspace`：16 个套件全绿。
- `cargo clippy --workspace --all-targets`：无警告。
- 100% / 150% 缩放：布局完好。200% 下工具栏横向溢出，但这是既有问题
  （916px 窗口 ÷ 2 = 458 逻辑点 < `MIN_WIDTH` 720），与本次改动无关。
- 混排基线：100% 下 CJK 与拉丁现在同落 y=66（改动前差 1px）。

边缘像素占比：0.60 → 0.585。**没有达到第五节那个 ≤0.56 的目标**，因为那个数字对应 14px，
而正文留在 13px。真正的改善来自配色（前景 80 → 27）和 `symmetric_rendering`（实心像素
27% → 49%），这两项是用户实际能看见的。

## 十、不做的事

- 不引入第三方字体文件（不打包 Noto、不打包 Inter）。用户要的是「和 Windows 统一」。
- 不把正文提到 14px：会改变每一行和每个控件的高度，是另一个设计决定。
- 不动 `ui_zoom` 的默认值（仍是 100）。
