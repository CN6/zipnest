# ZipNest 功能与界面优化建议（2026-11-27）

> 基线：v0.5.2（已发布，本机安装同为 0.5.2）。本文基于对仓库源码的逐项核对 +
> 本机实测（7z.dll 26.03 / 7-Zip CLI 26.04），不是凭印象列的清单。
> 只提建议、不改代码；优先级与取舍在文末。

## 0. 先给结论

ZipNest 现在的完成度很高：核心链路（解压/创建/加密/分卷/SFX/关联/右键/自更新/
无丢失保证）都做完了，最近十几个版本几乎全在打磨体验和修坑。所以"再加一堆功能"
不是正确方向，**真正值得投入的有三块**：

1. **右键菜单缺"一步到位"的常用动作** —— 这是国内用户最高频的入口，目前比
   WinRAR/7-Zip/Bandizip 少了最常用的两个动作，且"解压到…"还要再点一次对话框。
2. **压缩包内容是"只读"的** —— 不能追加、不能删除条目、不能测试完整性。会逼着
   用户装回 WinRAR；测试功能尤其便宜（7z.dll 自带 testMode），不做可惜。
3. **界面的细节欠打磨** —— 不是缺功能，而是缺"看起来像个成熟产品"的几处：没有
   行右键菜单、没有键盘导航、没有空状态引导、工具栏是纯文字、进度窗口信息密度低、
   完成时没有反馈。这些是投入最小、感知最强的部分。

下面分三部分：**A 功能补齐**、**B 界面升级**、**C 已验证但不建议做的事**，
最后给**优先级路由**。

## A. 功能补齐

### A1（强烈建议，性价比最高）测试压缩包（CRC 完整性校验）

**是什么**：工具栏和右键加一个「测试」：只读地把全部或选中条目解一遍并校验 CRC，
不写磁盘，结束逐条列出坏项和原因。

**为什么**：
- 网盘断流、U 盘拷一半、分卷缺一卷都是国内常见场景。现在只能"先解压，快结束
  才发现某个坏"，如果勾了「解压后删除压缩包」，源包可能已经没了。
- 和「绝不悄悄丢文件」的产品定位天然一致：先验再删，才敢删。
- **改造成本极低**：`7z.dll` 的 `IInArchive::Extract` 第一参就是 `testMode`，仓库
  `crates/archive-core/src/com/vtables.rs:72` 已有该字段、`extract.rs:1318` 目前
  硬编码为 0。加一个测试模式只需要在 `extract_to_disk` 上加一个开关，复用现有的
  回调、取消、进度、配额和失败上报，几乎零新逻辑。

**范围建议**：
- 只做"全部/选中"两种范围，复用现有进度窗口和结果窗口。
- 加密包先要密码（复用现有密码提示）。
- 分卷缺卷时明确说是哪一卷缺（引擎会给具体条目失败，逐条列出即可）。
- 把"测试结果"和"解压结果"共用一个结果窗口，不要新开一套。
- 预估 **S（<1 天）**。

### A2（强烈建议）右键菜单补全：免对话框的常用动词

**现状**（`crates/zipnest-ipc/src/shell.rs:359-406`）：文件右键只有
「ZipNest（打开）」「添加到压缩包…（进整页向导）」「解压到…（弹对话框）」；
文件夹/空白处只有「添加到压缩包…」。Win11 一级菜单（`packages/win11-shell`）
**只有"添加到压缩包…"一个动词**。

**缺的是国内用户最先按的那几下**：

| 应补的动词 | 行为 | 为什么重要 |
| --- | --- | --- |
| 解压到当前文件夹（或"解压到这里"） | 直接解到包所在目录，无对话框 | 下载完就地取文件的最高频动作 |
| 解压到 `<包名>\` | 直接解到包旁同名子文件夹，无对话框 | WinRAR/7-Zip 的默认习惯，不散落 |
| 添加到 `<文件名>.zip` | 直接生成包旁同名 zip，无对话框 | 日常"压一个东西发走"的最高频动作 |

**必须守住的不变量**（这条如果破坏，就违反了 "Nothing is ever lost"）：
- 免对话框解压**必须**沿用现有的"先 `count_conflicts`，只有真撞名才弹现有的
  覆盖询问"规则（v0.4.39 的成果），绝不能静默覆盖。
- **冲突自动改名目前对用户不可见**：`ExtractStats::renamed` 只记名字清洗
  （`extract.rs` 的测试钉着这个语义），引擎在 `OnConflict::Rename` 下的
  `unique_dest()` 改名不会进 `renamed` 清单。免对话框解压若固定用 rename，
  必须在结果窗口逐条列出"被改名"的条目，否则用户看到「完成」但文件名变了却
  不知道。**这是唯一需要动引擎的地方**：给 `ExtractStats` 增记冲突改名 +
  一条 IPC 事件 + 结果窗列表。
- 快速打包"添加到 `<名>.zip`"如果目标已存在，**不能**静默替换（`create.rs` 的
  临时文件 + rename 是原子替换，会覆盖旧包）。应先落到现有创建页的覆盖确认，
  或直接改用不撞名的名字并告知。

**范围建议（分两步）**：
- 第一步只做经典菜单的三个免对话框动词，给文件/文件夹动词设
  `MultiSelectModel=Player`（并让 `--extract` 接收多个路径），目标目录规则
  钉死。这一步整体 **M（1–3 天）**。
- 第二步再做 Win11 一级菜单的对应动词（新 CLSID + 清单多个 Verb，需重签 MSIX
  并实测旧包原地升级）。整件事到这一步才是 **L**。
- 砍掉：经典菜单里的动态包名（要进程内 `IContextMenu` 扩展，风险和量都不划算）、
  多选打包往经典菜单塞（交给 Win11 那条或第二批）。
- 新增 i18n 键必须中英双份；结果窗口写清输出位置。

### A3（建议）向已有压缩包追加 / 删除文件

**是什么**：打开 ZIP/7z/TAR 后可直接添加文件（含拖进窗口）或删除选中条目，
写入走临时文件 + 原子替换；RAR 和 gz/bz2/xz 单流格式明确标为"不可修改"。

**为什么**：WinRAR/7-Zip 用户习惯"打开包、拖几个文件进去、删掉不要的"。现在
ZipNest 只能新建，用户要么装回 WinRAR，要么解压-改-重压，还会丢掉原来的分卷、
加密或 SFX 设置。这是从"只能看和解"到"能管理压缩包"的关键一步。

**技术现状**：`create_archive` 永远走新建（`create.rs:861` 的 `UpdateItems` 不打开
`IInArchive`，没有 `NewArc`）。7-Zip 自己的客户端是"把现有包当 `IInArchive` 打开，
再把存活/新增条目的索引交给 `IOutArchive::UpdateItems`"。所以这是**可行的**，但：

- 7z 固实包的更新是整包重写，很慢，必须能取消且有进度。
- 加密包要密码，且不能悄悄改掉"加密文件名"设置。
- 分卷和 SFX 要重建卷序列/存根，复杂度高。
- 删除是破坏性操作，确认 + 失败回滚必须做扎实；原包在任何失败路径下都必须完好。

**范围建议**：
- 首版**只做 ZIP 和 7z 的"追加文件"和"删除选中条目"**，不做 TAR、不做分卷、
  不做 SFX（这些直接禁用并说明原因）。
- 追加/删除都先写临时文件，成功才原子替换；失败保留原包。
- 预估 **L（>3 天）**，但价值高（v4/5）。

### A4（建议）开放 7z.dll 已支持的更多可解格式

**现状**：引擎（随包 7z.dll 26.03）能解 `.zst/.tzst`、`Cab`、`Arj`、`Lzh`、
`Xar`、`Cpio`、`Rpm`、`Deb`、`Msi`、`Wim`、`Dmg`、`Chm`、`SquashFS`、
`VHD/VHDX`、`UDF`、`APFS`、`Ext` 等，但 App 里有四份硬编码白名单把它挡在门外：
`crates/zipnest-ipc/src/shell.rs:12` 的 `SUPPORTED_EXTENSIONS`、
`main.rs:5488` 的 `looks_like_archive`、打开对话框的过滤列表、创建格式 chips。

**为什么**：国内的 `.cab` 驱动包、`.msi` 安装包、老软件 `.chm` 帮助、开发者拿到的
`.zst`、IT 的 `.wim` 镜像，ZipNest 现在都打不开，只能另装 7-Zip。引擎明明支持，
投入产出比很高，也最符合"一个软件什么都能解"的卖点。

**风险与边界**：
- **不要**把 `.msi/.chm/.cab` 设成默认打开方式（那会改变双击行为：MSI 应该安装、
  CHM 应该打开帮助）。只能放进"打开方式 / 用 ZipNest 打开"，不能默认抢占。
- `.zst/.gz` 这类只能解不能建，UI 要标明。
- 识别要**靠引擎签名**而不是扩展名（现在 `looks_like_archive` 是扩展名判断），
  否则后缀与真实格式不符的文件会变多。
- 每格式单独的关联开关（数据模型 `Settings::assoc_extensions` 已支持，但 UI 现在
  只有一行状态文字，没有每格式勾选 —— 见 B6）。

**范围建议**：把"打开/拖放/命令行"的识别统一到一份集中列表（或引擎探测），
设置页加每格式开关，默认只保留现有的 9 个。预估 **M**。

### A5（建议）解压后保留「来自网络」标记（MOTW）

**是什么**：压缩包本身带 `Zone.Identifier`（浏览器下载标记）时，解压出的文件也
写上同样的标记，让 SmartScreen / Office 的下载来源保护继续生效；设置里可关。

**为什么**：从网盘/论坛下载的 zip，解压出的 exe 现在会丢掉"来自网络"标记，
Windows 就当它是本地文件，SmartScreen 和 Office 受保护视图不再提示——这是一次
静默的安全降级。7-Zip 26.03 专门修了"解压不保留 MOTW"的漏洞，WinRAR 7.30 也有
"Propagate mark of the Web"选项。ZipNest 主打安全，应当对齐。

**风险**：FAT32/exFAT/U 盘/网络共享写不了 ADS，会静默失败，UI 要说明；给解压出的
绿色软件打标记会让 SmartScreen 更常拦截，部分用户反感，所以**必须有开关**；
目录、符号链接和已存在文件不应重复打标。预估 **S**。

### A6（可选）拖出文件到资源管理器、列表右键/键盘、压缩率列

这三项都属于"WinRAR 用户肌肉记忆"，但各自成本不低：

- **拖出**（从列表拖到桌面/资源管理器）：egui/eframe 没有原生拖出支持，要在 UI
  线程跑 OLE `DoDragDrop`（阻塞帧循环），大文件还需延迟渲染或先落临时目录。
  **L**，建议暂缓。
- **行右键菜单 + 键盘导航**（方向键/Home/End/PgUp/PgDn/Enter/Shift 扩选 + 右键
  "打开/解压选中项到…/复制路径"）：自绘列表需要自持 cursor 状态（与 `anchor`
  并列），且行要用 `Sense::CLICK` 而非可聚焦控件，否则 egui 的空间导航会和自绘
  选择打架、一次按键两处响应。**M**，建议做（配合 B1/B2）。
- **压缩率/压缩前后大小/CRC 列**：引擎已经读 `kpidCRC`（`archive.rs:420`）但
  `EntryDto` 把它丢了；`kpidPackSize`/`kpidMethod` 从未读取。**M**，建议做
  （默认收起，允许空值）。

### A7（可选）批量解压多个压缩包

**现状**：拖入多个文件目前只会被判为"新建压缩包"的源（`main.rs:5946` 只对
"全是压缩包且恰好一个"走 `open_archive`），十个 zip 拖进来会打开创建页，而不是
批量解压。

**为什么**：下载一批分发包/资料包时，"全选→右键→解压"是常见动作。

**范围建议**：在 `zipnest-ipc` 新增一个批量解压命令（worker 里逐包
open→extract→close，7z.dll 完全不动），拖入多个压缩包时弹一次确认，根目录默认
取共同父目录，冲突固定用"自动重命名"，结束时按包列出成功/失败。首版砍掉 Win11
批量动词、逐包密码弹窗、可配置冲突策略。预估 **M**。

---

### A8（可选，但和"中文优先"最相关）旧编码压缩包文件名

**先纠正一个流传的判断**：本机实测，**无 UTF-8 标志、cp936 字节的 ZIP 条目名，
当前 7z.dll 其实能正确解码**（ACP=936 兜住了），也会正确落盘。真正会乱的是：

- **无 UTF-8 标志、但实为 UTF-8 文件名**的包（很多非 Windows 工具产出）；
- 在**非中文 Windows** 上打开 GBK 包（ACP 不是 936）；
- Big5 / Shift-JIS 的老包。

**好消息**：不需要自己解析 EOCD/中央目录。官方 7z.dll 的读侧 handler 实现了
`ISetProperties`，`cp`（VT_UI4）属性可以直接切换解码用代码页，GBK/GB18030/
Big5/Shift-JIS 实测都能正确解出，带 UTF-8 标记的条目不受影响。所以这件事是
**M 而不是 L**。

**建议做法（保守）**：
- 默认保持引擎原行为（不要自动强设代码页，猜错会把本来正确的名字改坏）。
- 只在条目名出现成片私用区字符（U+EF00–U+EFFF）时给一行提示"文件名可能乱码，
  试试 GBK / Big5 / 日文"，点选后先预览前几个正确译名，确认才重开归档并重建列表。
- 设置页留一个手动"文件名编码"下拉兜底。
- 落盘仍走 `plan_entry_paths`、`renamed` 照旧上报，保证"绝不丢条目"。

### A0（已取消，2026-11-27 用户决定）压缩/解压多线程

**结论：不做。** 用户判断解压速度已够快，不值得再投入（决策日期 2026-11-27）。
本节只保留实测事实，防止后续 session 重新提这条。

实测（7z.dll 26.03 / 7-Zip 26.04 CLI，20 逻辑核）：

| 场景 | mt=1 | mt=on（默认） | 结论 |
| --- | --- | --- | --- |
| 创建 ZIP，200 个文件 | 0.5 s | 0.1 s | 多文件打包**早就**是多线程（`apply_properties` 已传 `mt=on`） |
| 创建 ZIP，单个 100 MB 文件 | 3.6 s | 3.6 s | 单文件单流，Deflate 串行是引擎上限 |
| 创建 ZIP，单个 131 MB `-mx=9` | 358 s | 358 s | `-mmt` 对它无效 |
| 解压 7z LZMA2，506 MB，3.4:1 | 56 MB/s（`-mmt=1`） | 176 MB/s | 解压侧 **mt 有收益** |
| 解压 ZIP 单文件，506 MB，3.0:1 | — | 116 MB/s | 已够快 |

要点：多文件已经并行；剩下的"单文件/解压多线程"收益存在但用户已拍板不做，
不要重复提这条，也不要为了它改 `IInArchive`/换引擎。

## B. 界面升级

> 先说一句：README 里的两张截图是 **v0.4.0 时代**的旧图（浅色、标题栏浅灰），
> 不代表现状。现状已经跟随系统深色、标题栏在 egui 0.37 下**已自动变深**
> （`sync_window_theme` 默认开启，见 `egui-0.37/src/memory/mod.rs:334`）。
> 所以"深色标题栏"这条已经被证实**不用做了**（只剩 1px 窗口边框可顺手补）。

### B1（首推，投入最小感知最强）文件列表的行右键菜单

在行上右键弹「打开 / 解压选中项到… / 复制路径 / 选中全部 / 取消选择」。
这是"看起来像成熟产品"最直接的一步，用户不用再猜"双击才能打开"。**S–M**。

### B2（首推）键盘导航与焦点环

方向键 + Home/End + PgUp/PgDn + Enter（目录进入、文件打开，复用现有两条分支）
+ Shift 扩选，焦点环用主题蓝 1px、仅键盘操作后出现并自动滚入视野。配合 B1
一起做，体验的"专业感"会明显上一档。**M**。

### B3（建议）进度窗口显示"当前文件"

`JobEvent::Progress` 现在带 bytes/items/speed/ETA，但**没有当前条目路径**，
进度窗口只能显示字节数。加一个字段（引擎回调里的 `ExtractProgress.current_path`
已经有了，只是没有穿过 IPC），进度窗口显示"正在解压 `docs/xxx.txt`"。**S**。

### B4（建议）空状态与首次启动引导

现在空状态是一个虚线框 + 文字 + 一个"打开压缩包"按钮（`empty_state()`）。
建议补：
- 一行"把压缩包拖到这里"更醒目（现有提示的视觉层级偏弱）；
- 首次启动时一行"已自动设为默认解压软件，可在设置里改"的说明。

> 2026-11-27 用户决定：**不做"最近打开"列表**，本条已收窄为纯引导文案/视觉。

**S**，感知强。

### B5（建议）完成反馈：非模态提示 + 任务栏闪烁

现在任务结束只有进度窗口里的文字，窗口最小化或在别的程序上时用户不知道。
建议：
- 任务完成且窗口未聚焦时用 `ViewportCommand::RequestUserAttention`（winit 已封装
  `FlashWindowEx`）闪一下任务栏；
- 成功时在状态栏用一个 3 秒自动消失的**非模态**提示条（InfoBar），而不是弹窗；
- 失败仍然弹现有错误窗（必须让用户看到）。

**S**。

### B6（建议）设置页：每格式关联矩阵 + 按需展开高级项

- 现在"系统集成"只有一行状态文字，数据模型 `assoc_extensions` 的每格式清单
  没有 UI。加一排每格式勾选（默认全选，`.msi/.chm` 等新格式默认不选，见 A4），
  让"我只想让 ZipNest 管 zip/7z"这类需求可见可控。
- 设置页目前是一长列卡片，Zoom/解压上限/自动关闭等可以收进"高级"折叠区，
  首屏只留语言、外观、关联三块。**M**。

### B7（可选）工具栏与状态栏的信息层级

- 工具栏现在是三个文字按钮 + 包名 + 右侧三个文字按钮，纯文字、无图标。建议给
  主操作（打开/新建/开始解压）加 16px 单色图标（可以自己画，不引新依赖），
  hover 才显示快捷键。
- 状态栏现在只显示条目数/选中数 + 检查更新 + 支持我们。建议左侧常驻显示
  "包格式 · 总大小 · 压缩率"（数据见 A6），右侧保留更新和捐赠入口。

**M**，但会明显改变"第一眼观感"。

### B8（可选）统一对话框外观 + 遮罩

现在 extract/conflict/password/update/error/donate 各自用 `egui::Window`，位置、
宽度、边距不完全一致，主窗口后面没有遮罩。建议抽一个 `theme::dialog()` 包装：
统一宽度、居中、圆角、标题栏、底部按钮右对齐、打开时主窗口加一层半透明遮罩
（egui 的 `Area` + 半透明矩形即可）。**M**，但一致性收益大。

### B9（可选）拖放悬停覆盖层

现在拖文件到窗口会直接触发动作，但拖动过程中**没有视觉反馈**。建议在
`raw_input.dropped_files` 期间画一层"松手即可打开/打包"的覆盖提示。**S**。

### B10（不建议做）

- **Mica/亚克力背景**：需要 `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)`
  + 透明窗口 + egui 的透明清屏，在 glow/OpenGL 下容易出现黑边、闪烁、和
  "最大化的窗口边缘 1px 亮线"这类顽疾，而且和"稳定、零依赖"的定位不符。
- **自绘标题栏**：可做，但要自己实现拖动/双击最大化/贴边分屏/系统菜单/DPI，
  风险远大于收益（现成的系统标题栏已经跟随深色）。
- **托盘图标 / 常驻后台**：已被明确移除，不建议回退。

## C. 已验证、但**不建议**做的事（避免走弯路）

这些是调研中出现、但经核对不适合 ZipNest 的：

| 提案 | 为什么不建议 |
| --- | --- |
| 自动编码探测（猜 GBK/Big5/UTF-8） | 猜错会把本来正确的名字改坏；用 A8 的"提示 + 手动选择"更稳。 |
| 把 `.msi/.chm/.cab` 设为默认打开方式 | 会改变双击语义（MSI 应安装、CHM 应打开帮助），只能进"打开方式"。 |
| 经典右键菜单里显示动态包名 | 需要进程内 `IContextMenu` 扩展注入 Explorer，风险和量都不划算；动态能力交给 Win11 一级菜单。 |
| 自己解析 ZIP 中央目录来修文件名 | 引擎 `ISetProperties("cp")` 已经能解决（A8），自己解析要处理 SFX/Zip64/分卷/混编码，收益反而小。 |
| 托盘、任务中心、内嵌预览窗格 | 都是已明确移除的设计，不建议回退。 |
| 引入 WebView/Electron/新 UI 框架 | 与"3.6 MB、零运行时依赖、原生"的产品身份冲突。 |
