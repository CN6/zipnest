# 计划：设置页 / 新建压缩包 / 解压对话框 重新排版 (v0.4.32)

## 问题（截图实测，720×620，100% 缩放）

设置页：
1. 两个互相打架的左边缘：分区标题（常规 / 解压 / 系统集成）贴页面最左；字段说明右对齐在 84pt 处。
2. 帮助文字被缩进到控件列（x≈96），形成一条参差的右漂块。
3. 复选框行没有说明文字，勾选框被右对齐推到说明列里，读起来像挂在上一行上。
4. 长提示（自动关闭窗口那条）一行拉满 690pt，没有行长上限。
5. 字段说明（「默认解压目录」）距它的控件 84pt，标签和控件在视觉上不成一组。

新建压缩包（470 宽）：
6. 「tar.xz」被窗口右边切掉 —— 6 个 chip 挤在 84+22pt 说明列之后的控件列里。
7. 同样的右对齐说明列，同样参差的帮助文字。

解压对话框：
8. 说明列 + 控件列在 430pt 宽的窗口里浪费了近 1/3 宽度，目标文件夹输入框被压到 260pt。
9. 按钮行贴着内容左边缘，和上方字段没有共同的左边缘（字段从 84pt 开始）。

## 依据的规范

- WinUI 3 / Windows 11 Settings：设置行由「标题 + 描述」和右侧控件组成；设置项分组放进带 1px 描边、8pt 圆角的卡片。
- Fluent 2 type ramp：正文 14、Caption 12；次要文字用 60% 不透明度的文字色。
- 8pt 间距刻度（4pt 用于微调）：标签与控件之间 4，行与行之间 8–12，组与组之间 24。
- 表单标签放在控件上方（Microsoft Learn「Forms」、Material text field），而不是并排 —— 并排会在窄窗口里制造第二条左边缘，正是这里的病因。
- Apple HIG：同一屏内只用一条对齐轴。

## 改法

1. `theme.rs`
   - 删除 `form_row` / `hint_indented`（固定说明列的来源）。
   - 新增 `field(ui, label, has_help, add)`：说明单独一行（12.5pt 次要色），其后可选「?」，4pt 后是控件（占满可用宽度），行末 12pt 间隔。
   - `hint` 增加行长上限（560pt），保持 11.5pt 次要色、自动换行、左对齐。
   - 新增 `group(ui, add)`：设置分组卡片（window_fill 底、1px 描边、8pt 圆角、16pt 内边距）。
   - `section` 上间距 24pt、下间距 8pt。
   - `chip` 保持（描边/实心蓝）。
2. `settings_body`：分区标题 → `group` 卡片 → 卡片内 `field` / 复选框行。所有控件从卡片内容左边缘开始，一条轴。
3. `create_wizard_ui`：全部改 `field`；chip 行用 `horizontal_wrapped`，窗口窄时换行而不是被切。
4. `extract_dialog` / `password_dialog`：改 `field`，输入框占满宽度；按钮行保留在左下（WinUI ContentDialog 的位置），但加一条上方分隔。
5. 版本 0.4.32 + CHANGELOG（用户能感知的条目）。
