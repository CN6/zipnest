## A1 测试压缩包（S）

### 目标
工具栏和右键菜单都有\"测试\"：只读地把全部或选中条目解一遍并校验 CRC，不写磁盘；
结束复用现有结果窗口逐条列出坏项和原因。加密包先要密码；分卷缺卷逐条列出。

### 引擎
`crates/archive-core/src/extract.rs`

- `ExtractOptions` 增加 `test_mode: bool`（或新函数 `test_archive`——选后者更干净：
  测试模式不需要 dest、不写盘、不建目录，混进 `extract_to_disk` 会让\"目标目录\"这
  个概念在同一函数里说谎）。做法：抽出共同的回调状态机，`test_mode` 只影响
  `GetStream`（返回 null → 引擎自己解到内存里只算 CRC）与 `SetOperationResult`
  的处理。`IInArchive::Extract` 第三参传 1（`vtables.rs:72` 已有该字段）。
- 结果类型：复用 `ExtractStats` 的语义（`failed` 非空即失败、逐条原因），另加
  `tested: u32`（校验通过的条目数）。失败的条目沿用 `error.corrupt` / `error.entry_io`
  这些已有 key；缺卷时引擎给的是条目的数据错误，走 `failed` 列表。
- 配额：测试模式不写盘，不需要 `ExtractQuota`；但为防止炸弹条目把 CPU 烧穿，
  仍然用 `ExtractQuota` 统计解出的字节（charge 后不落盘），超限 → `error.quota_exceeded`。
- 取消：沿用现有 `progress` 闭包返回 false → `Cancelled`。

### IPC
`crates/zipnest-ipc/src/service.rs`

- `pub fn test_archive(&self, id, paths: Vec<String>, password: Option<String>) -> Result<u64, IpcError>`：
  与 `extract_with_delete` 同一个选择展开（`select_entries`）、同一个密码检查、
  同一个 `JobManager`。成功/失败都发 `job_finished`；失败条目走 `extract_failed`
  事件（结果窗已经会逐条列出）；成功时发一条新的 `test_finished` 事件携带
  `{tested, files}`，让 UI 说\"已校验 N 个文件，全部完好\"而不是\"解压完成\"。
- 结果窗口复用：`JobState` 增加 `kind: JobKind`（Extract/Create/Test），标题与
  成功文案按 kind 取 i18n key。

### UI
`apps/zipnest-native/src/main.rs`

- 工具栏：`开始解压` 旁边加一个次要按钮 `测试`（只有打开归档时可用）；右键菜单
  同一入口。开始前如果归档有加密条目且没有密码，走现有 `password_prompt`，
  `PasswordThen` 增加 `Test(TestRequest)` 分支。
- 结果窗口：成功 `job.test.ok`（\"已校验 N 个文件，全部完好\"）；失败 `job.test.failed`
  + 现有 `error_detail` 逐条列表。
- i18n：`test.start`、`test.title`、`job.test.ok`、`job.test.failed`、
  `test.scope_all`、`test.scope_selected`（中英双份）。

### 测试
- `crates/archive-core/tests/engine.rs`：好包测试通过；`fixtures/corrupt.zip`
  测试失败且带条目；分卷缺卷（造一个 `.7z.001` 没有 `.002`）失败并列出。
- `crates/zipnest-ipc/tests/service.rs`：`test_archive` 对 `plain.zip` 发
  `test_finished` 且 `tested == 4`；对 `corrupt.zip` 发 `extract_failed`。
- 加密包：`fixtures/enc.7z` 无密码 → `error.password_required`。

### 风险
- 引擎的 testMode 对不同 handler 的行为要实测（7z/ZIP/RAR）。若某 handler 在
  testMode 下仍然调用 `GetStream`，我们的回调返回 null 即可——7-Zip 自己的客户端
  就是这么做的。

## B1 行右键菜单 + B2 键盘导航（M）

### B1 行右键菜单
- 自绘行已经用 `Sense::click()`；右键用 `resp.secondary_clicked()`。菜单用
  `egui::Popup`/`egui::menu` 挂在行 rect 上。菜单项：打开 / 解压选中项到… /
  复制路径（选中多项时\"复制路径\"复制全部，一行一个）。
- 右键未选中行时先选中它（Explorer 行为）；右键已选中的行保留多选。
- \"解压选中项到…\" = 现有 `begin_extract_dialog()`（selection 已经是范围）。
- \"复制路径\" = 归档内路径（`e.path`），不是磁盘路径——用户要的是包内路径。

### B2 键盘导航
- `App` 增加 `cursor: Option<usize>`（与 `anchor` 并列，索引排好序的 `rows`）。
- 仅在列表区域有键盘焦点时响应（`ui.memory` 的焦点 id 绑定到列表容器，
  `Sense::click()` 的行不抢 egui 焦点系统的空间导航）。按键：
  - ↑/↓：移动 cursor 一行，并清空选择、选中新行（Shift 则扩选）；
  - Home/End：第一/最后一行；PgUp/PgDn：按可见行数（`ROW_H` × 视口高）；
  - Enter：目录进入 / 文件打开（复用 `navigate` / `open_entry`）；
  - Shift+↑/↓/Home/End/PgUp/PgDn：从 anchor 扩选；
  - 空格：切换当前行选中（不移动）。
- 焦点环：主题蓝 1px 的 `Stroke` 画在行 rect 上，**只在最近一次输入是键盘时**显示
  （`ctx.input(|i| i.key_pressed(...))` 置 `keyboard_nav = true`，鼠标点击置 false）。
- 滚入视野：`ui.scroll_to_rect(row_rect, Some(Align::Center))`，只在 cursor 因键盘
  移动时调用。
- 不能与 egui 的空间导航打架：行保持 `Sense::click()`，列表容器用
  `Sense::hover()` + 自己的 `interact` 抢键盘；确保 `egui_wants_keyboard_input()`
  为 false 时才处理（搜索框/对话框有焦点时让位）。

### 测试
- 纯逻辑抽函数：`next_cursor(len, cur, key, shift, anchor, selected) -> (Option<usize>, HashSet)`
  之类，单测覆盖 Home/End/PgUp/PgDn/Shift 边界（列表为空、只有一行、在首/末行）。
- 菜单动作本身走真实截图验证（`scripts\dev-run.ps1` + `ui-shot.ps1`）。

## A2 第一步：经典右键免对话框动词（M）

### 目标
文件右键菜单（`crates/zipnest-ipc/src/shell.rs` 的 `file_menu_ops`）新增：
- 解压到当前文件夹（`--extract-here "%1"`）
- 解压到 `<包名>\`（`--extract-to-subdir "%1"`）
- 添加到 `<文件名>.zip`（`--add-here "%1"`）

并给文件/文件夹动词设 `MultiSelectModel=Player`，`--extract*` 接收多个路径。

### 不变式
- 免对话框解压必须先 `count_conflicts`，只有真撞名才弹现有覆盖询问。
- 冲突自动改名目前对用户不可见：`ExtractStats::renamed` 只记名字清洗。
  **必须**给 `ExtractStats` 增记冲突改名（新字段 `conflict_renamed: Vec<RenamedEntry>`）
  + IPC 事件 `extract_conflict_renamed` + 结果窗逐条列出。
- 快速打包\"添加到 `<名>.zip`\"目标已存在时不能静默替换：先落到创建页的覆盖确认，
  或改用不撞名的名字并告知。本轮采用前者（复用 `create_confirm_overwrite` 逻辑）。
  实际上免对话框动词不能弹创建页——用户要的是\"一步到位\"。所以：已存在就改用
  `name (2).zip` 并在结果窗写明\"已另存为 …\"，绝不覆盖。

### 引擎改动
`extract.rs` 的 `disk_get_stream`：`OnConflict::Rename` 分支里 `unique_dest` 成功时，
把 `(raw_path, 目标相对路径)` 记到新字段 `conflict_renamed`。注意要与 `renamed`
区分：`renamed` 是名字清洗，`conflict_renamed` 是撞名改名。

### CLI
`main()` 解析 `--extract-here` / `--extract-to-subdir` / `--add-here`，
`LaunchRequest` 增加对应变体。单实例队列格式扩展。
- 解压到当前文件夹：`dest = archive.parent()`；
- 解压到 `<包名>\`：`dest = archive.parent()/<stem>`；
- 添加到 `<文件名>.zip`：`sources = 所有参数`，`dest = 第一个参数的 parent()/<stem>.zip`，
  已存在则 `<stem> (2).zip`。

### 测试
- `shell.rs`：新增动词的注册键与命令行。
- `extract.rs`：冲突改名出现在 `conflict_renamed` 而不是 `renamed`。
- `service.rs`：`extract` 撞名后发 `extract_conflict_renamed`。
- `main.rs` 的纯函数：目标目录推导（有单测空间）。

## A3 向已有 ZIP/7z 追加/删除（L）

### 目标
打开 ZIP/7z 后可直接添加文件（含拖进窗口）或删除选中条目，写入走临时文件 + 原子替换；
RAR 和 gz/bz2/xz 单流格式明确标为\"不可修改\"。首版不做分卷、不做 SFX、不做 TAR。

### 引擎
`crates/archive-core/src/create.rs`（或新 `update.rs`）：
- 新函数 `update_archive(arc: &Archive, dest, changes: &[UpdateOp], opts, progress)`：
  打开旧包当 `IInArchive`（已有 `Archive::open`），把\"存活条目 + 新增条目\"的索引
  交给 `IOutArchive::UpdateItems`。`IArchiveUpdateCallback::GetUpdateItemInfo` 需要
  三种模式：保留旧条目（`newData=0,newProps=0,indexInArchive=i`）、删除
  （`newData=0,newProps=1,indexInArchive=i` 且 `kpidIsDir`... 实际上删除是
  `newData=0, newProps=0` 且**不**出现在新索引表里——即删除 = 不提交该索引）、
  新增（`newData=1,newProps=1,indexInArchive=u32::MAX`）。7-Zip 客户端做法：
  为原包的每个条目提交一次 `GetUpdateItemInfo`，删除的条目不提交。
- 现有 `outcallback::UpdateCallback` 只支持\"全部新增\"；扩展为 `UpdateEntry`
  枚举（Keep{index_in_archive}/Add{source}/Remove）。
- `write_archive` 的临时文件 + 原子替换逻辑复用。

### 风险
- 7z 固实包的更新是整包重写，必须能取消且有进度。
- 加密包要密码，且不能悄悄改掉\"加密文件名\"设置——保留原包的 `he` 状态需要先
  读 `kpidEncrypted`（archive-level）并沿用。
- 删除是破坏性操作，确认 + 失败回滚必须做扎实；原包在任何失败路径下都必须完好。

### UI
- 工具栏加\"添加文件…\"与\"删除选中条目\"（仅 ZIP/7z 可用，其他格式禁用并注明原因）。
- 删除要确认（复用冲突询问的样式）。
- 拖文件到已打开的归档窗口 → 询问\"添加到当前压缩包？\"。

### 测试
- 新增条目后旧条目仍在、内容不变；
- 删除条目后原包其余条目完好；
- 取消/失败后原包完好（临时文件不落盘）；
- 加密包更新后仍需密码且旧内容可读。

## A5 MOTW（S）

- 解压前检查源包是否带 `Zone.Identifier` ADS（`std::fs::read(archive + ":Zone.Identifier")`）。
- 带标记时给每个解出的文件写同样的 ADS；目录、符号链接不写。
- 设置项 `preserve_motw: bool`（默认开）。FAT32/exFAT/U盘/网络共享写不了 ADS 时
  静默失败但界面说明（结果窗一行\"有 N 个文件因目标文件系统不支持而未能保留网络标记\"）。
- 测试：NTFS 临时目录上写读 ADS；非 NTFS 只能靠真机验证。
